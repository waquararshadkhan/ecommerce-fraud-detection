# E-Commerce Fraud Detection

Can we spot fraudulent purchases on an online store before they go through? This project
builds a fraud detection model on **151,112 real e-commerce transactions** and turns it into
a practical block / review decision rule.

**Tools:** Python, Pandas, Scikit-learn
**Data:** Kaggle e-commerce fraud dataset: `Fraud_Data.csv` (purchases) and
`IpAddress_to_Country.csv` (IP ranges → country). Not included in this repo; download it from
Kaggle and place both files in `data/`.

---

## Key results

| | |
|---|---|
| Transactions | **151,112** (14,151 fraud = **9.4%**) |
| Best model | Random Forest (class-weighted) |
| ROC-AUC | **0.836** |
| Fraud recall | **51% → 70%** after handling class imbalance |
| Auto-block tier | **100% precision** at a 0.8 probability threshold |

## What I found

**1. Fraudsters buy instantly.**
**53.7% of fraudulent purchases happened within 1 second of signup.** No genuine customer did
this. Real users typically wait weeks (median about 60 days).

**2. Shared devices and IPs give fraud away.**
A device used by 1 account had about 3% fraud. Devices shared by 5+ accounts were **80%+ fraud**.
The same pattern holds for IP addresses.

**3. Three engineered features did almost all the work.**
`device_user_count` (39.7%), `seconds_to_buy` (34.5%) and `ip_user_count` (20.4%) make up
**94.6% of the model's feature importance**.

## Approach

1. **Feature engineering:** time from signup to purchase, accounts per device and per IP,
   purchase hour and weekday, and IP → country mapping using range-based joins (`merge_asof`).
2. **Imbalanced data:** stratified train-test split (80/20) and `class_weight='balanced'`.
   Accuracy is misleading here: a model that predicts "not fraud" for everyone is about 91% accurate
   but catches nothing. So I evaluated precision, recall and ROC-AUC.
3. **Models:**

   | Model | Precision (fraud) | Recall (fraud) | ROC-AUC |
   |---|---|---|---|
   | Logistic Regression | 0.902 | 0.514 | - |
   | Logistic Regression (balanced) | 0.522 | 0.701 | 0.833 |
   | Random Forest (balanced) | 0.543 | 0.696 | **0.836** |

4. **Business decision rule:** instead of one cut-off, a tiered threshold:

   | Risk score | Action | Result |
   |---|---|---|
   | ≥ 0.8 | **Auto-block** | 100% precision, catches 52% of fraud with zero false blocks |
   | 0.3 – 0.8 | **Manual review** | Brings total fraud caught to about 70% |
   | < 0.3 | Approve | |
